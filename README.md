# Rasel Rana — Personal Website

The personal website and portfolio of **Rasel Rana**, Manager (Technical) at Bangladesh Telecommunications Company Limited (BTCL).

**Live site:** [raselrana.com.bd](https://raselrana.com.bd)

## Overview

A content-driven portfolio built with Next.js. It presents professional background, experience, achievements and downloadable documents, and includes a small admin panel for managing the Achievements content without touching the code.

> Much of the written content is still sample text while the site is being built out. Real content is being added section by section.

## Features

- **Portfolio pages** — Home, About, Journey, Experience, Achievements, Projects, Skills, Education, Publications, Downloads and Contact.
- **Admin panel** — a password-protected dashboard at `/admin` to add, edit and delete achievements (competitions, judging, sports, leadership, press and memberships), stored in MongoDB.
- **Contact form** — delivers messages by email through Resend, with server-side validation and a honeypot field against bots.
- **Download tracking** — document downloads are counted in MongoDB and reported to Vercel Analytics.
- **Light and dark themes** — follows the system setting, with a manual toggle.
- **Fast, accessible pages** — content is rendered on the server and readable without JavaScript; animations are CSS-only and respect the reduced-motion setting.
- **Blog** — `/blog` is served by a separately deployed blog application through a rewrite.

## Getting Started

### Prerequisites

- Node.js 20.9 or later
- A MongoDB database (for example, a free [MongoDB Atlas](https://www.mongodb.com/atlas) cluster)
- A Resend API key, if you want the contact form to send email

### Installation

```bash
git clone https://github.com/raselrana-admin/raselrana-web.git
cd raselrana-web
npm install
```

### Environment variables

Create a `.env.local` file in the project root:

| Variable | Required | Purpose |
| --- | --- | --- |
| `MONGODB_URI` | Yes | MongoDB connection string |
| `MONGODB_DB` | No | Database name (defaults to `raselrana`) |
| `RESEND_API_KEY` | For the contact form | Resend API key |
| `CONTACT_EMAIL_TO` | For the contact form | Address that receives contact messages |
| `CONTACT_EMAIL_FROM` | No | Sender address on a domain verified in Resend |
| `ADMIN_EMAIL` | For the admin panel | Email used to sign in |
| `ADMIN_PASSWORD_HASH` | For the admin panel | Password hash, generated by the command below |
| `SESSION_SECRET` | For the admin panel | Secret used to sign the session cookie |
| `BLOG_DOMAIN` | For `/blog` | Base URL of the separately deployed blog |

Generate the admin password hash and session secret:

```bash
npm run hash-password
```

The command asks for a password and prints the `ADMIN_PASSWORD_HASH` and `SESSION_SECRET` lines to copy into `.env.local`. The password itself is never stored.

### Run locally

```bash
npm run dev
```

Open [http://localhost:3000](http://localhost:3000).

## Admin Panel

1. Set `ADMIN_EMAIL`, `ADMIN_PASSWORD_HASH` and `SESSION_SECRET` as described above.
2. Open `/admin` and sign in.
3. On first use, choose **Import starter content** to copy the built-in achievements into the database. After that, everything on the Achievements page is edited from the dashboard.

Sign-in is limited to a single admin account. Sessions last seven days, and repeated failed attempts from one address are temporarily blocked.

## Project Structure

```
src/
├── app/                  # Routes: pages, API routes, admin panel
│   ├── admin/            # Sign-in, dashboard and server actions
│   └── api/              # Contact form and download tracking endpoints
├── components/
│   ├── layout/           # Navbar, mobile menu, footer
│   ├── sections/         # Page sections, grouped by page
│   ├── admin/            # Admin dashboard components
│   └── ui/               # Shared pieces (logo, headers, network map)
├── lib/
│   ├── data/             # Site content as plain JavaScript files
│   ├── services/         # Database access
│   └── auth/             # Admin sign-in and session handling
├── views/                # Server components that read from the database
└── proxy.js              # Protects /admin routes
```

Most page content lives in `src/lib/data/` — to change the text on a page, edit the matching file there. Footer links (including social links) are in `src/lib/data/site.js`.

## Deployment

The site is deployed on Vercel. Merging into `main` triggers a production deployment to [raselrana.com.bd](https://raselrana.com.bd).

All environment variables listed above must also be set in the Vercel project settings (for both Production and Preview), since `.env.local` is not uploaded.

## Development Workflow

- Each feature is developed on its own `feature/<name>` branch.
- Feature branches are merged into `develop` through pull requests.
- `develop` is merged into `main` to release.
